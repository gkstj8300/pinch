## 3. 초기 셋업 (1회)

```bash
# 1) 의존성 설치
pnpm install

# 2) 환경변수 복사
cp .env.example .env

# 3) PostgreSQL(PostGIS) 컨테이너 기동
pnpm db:up

# 4) Prisma 마이그레이션 적용
pnpm db:migrate

# 5) 보강 SQL 실행 (PostGIS 트리거, CHECK 제약, 부분 인덱스)
docker exec -i pinch-postgres psql -U pinch -d pinch_dev < prisma/migrations/post-init.sql

# 6) Prisma 클라이언트 생성
pnpm prisma:generate
```

## 4. PoC 실행 절차

### 4.1 시드 + 서버 기동

```bash
# 시드: 사업주 1, 워커 200, 모집 1명 공고 1개
pnpm db:seed
# → 출력에서 JOB_ID, WORKER_ID_START 확인

# API 서버 기동 (별도 터미널)
pnpm start:dev
```

### 4.2 부하 테스트

```bash
# 시드가 출력한 ID를 환경변수로 주입
JOB_ID=<시드_출력값> WORKER_ID_START=<시드_출력값> pnpm stress

# 또는 Docker로:
docker run --rm -i --network=host \
  -e JOB_ID=1 -e WORKER_ID_START=2 \
  -v "$PWD/k6:/scripts" grafana/k6 run /scripts/apply-stress.js
```

### 4.3 합격 기준

```
MATCHED (201)  : 1     ← 정확히 1명만 매칭
CONFLICT (409) : 199   ← 나머지 모두 정원초과
OTHER          : 0
P99 latency    : < 300 ms
```

### 4.4 DB 직접 검증 (보조)

```bash
docker exec -it pinch-postgres psql -U pinch -d pinch_dev -c \
  "SELECT id, recruit_count, confirmed_count, status FROM jobs;"
# 결과: confirmed_count=1, status=CLOSED 이어야 함

docker exec -it pinch-postgres psql -U pinch -d pinch_dev -c \
  "SELECT COUNT(*) FROM matches WHERE status='MATCHED';"
# 결과: 1
```

## 6. 핵심 설계 요약 — `MatchesService.apply()`

### 동시성 차단 메커니즘

```sql
UPDATE jobs SET confirmed_count = confirmed_count + 1
WHERE id = ?
  AND status = 'OPEN'
  AND confirmed_count < recruit_count   ← race 차단 핵심
  AND ...자격 조건들
```

- **affected rows == 1** 일 때만 자리 확보 성공
- PG row-level lock 이 같은 행에 대한 동시 UPDATE 를 직렬화
- `SELECT-후-UPDATE` 패턴을 쓰지 않음 → race window 없음
- 추가로 `Match @@unique([jobId, workerId])` 가 중복 지원도 차단

### 진단 (실패 사유 분기)

UPDATE 실패 시(affected=0) `diagnoseFailure()` 로 정확한 사유 반환:

| 사유 | 의미 |
|---|---|
| `JOB_NOT_FOUND` | 공고 미존재 또는 soft delete 됨 |
| `JOB_CLOSED` | 이미 마감(다른 상태) |
| `CAPACITY_FULL` | 정원 초과 (선착순 패배) |
| `SCORE_TOO_LOW` | 핀치 스코어 컷오프 미달 |
| `VERIFICATION_REQUIRED` | 본인인증 필요 |
| `JOB_ALREADY_STARTED` | 시작 시각 지남 |
| `ALREADY_APPLIED` | 같은 워커 중복 지원 |

## 8. 트러블슈팅

| 증상 | 원인 / 해결 |
|---|---|
| `prisma migrate dev` 가 `postgis` 확장 못 찾음 | Docker 이미지가 `postgis/postgis:17-3.5` 인지 확인 |
| k6 결과 MATCHED > 1 | `apply-stress.js` 의 BASE_URL 이 잘못되어 다른 서버 호출 중일 가능성 |
| k6 결과 OTHER > 0 | 서버 에러 발생 — `pnpm start:dev` 로그 확인 |
| `BigInt` 직렬화 오류 | 응답에서 `.toString()` 호출 누락 — controller 확인 |
