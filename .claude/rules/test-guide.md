## 2. 개요

본 문서는 프로젝트 내 모든 기능 구현 후 진행해야 하는 테스트 및 검증 절차를 정의한다. Claude는 코드를 작성하거나 수정할 때 반드시 아래 규칙을 준수한다.

---

## 3. 기본 원칙 (Core Principles)

- **"구현 후 테스트" 필수:** 기능 구현 또는 버그 수정 후에는 반드시 해당 코드가 의도대로 동작하는지 확인하는 테스트 과정을 거친다.
- **테스트 코드 우선 (Test-First Mindset):** 가급적 구현과 동시에 혹은 구현 직후 단위 테스트(Unit Test)를 작성한다.
- **실패 케이스 고려:** 성공 시나리오뿐만 아니라 발생 가능한 예외 상황(Edge Cases)을 반드시 테스트 설계에 포함한다.

---

## 4. 테스트 단계별 체크리스트 (Testing Checklist)

### 4.1 정적 분석 및 자가 검토

- [ ] 구문 오류(Syntax Error)가 없는가?
- [ ] 정의되지 않은 변수나 함수를 참조하고 있지는 않은가?
- [ ] 프로젝트의 코딩 컨벤션(Linting)을 준수했는가?

### 4.2 단위 테스트 (Unit Testing)

- **독립성:** 각 함수나 모듈은 외부 의존성 없이 독립적으로 테스트되어야 한다. (필요 시 Mocking 활용)
- **커버리지:** 주요 비즈니스 로직에 대한 테스트 커버리지를 최소 80% 이상 확보한다.
- **명명 규칙:** 테스트 함수명은 `test_[함수명]_[조건]_[기대결과]` 형식을 권장한다.

### 4.3 엣지 케이스 및 예외 테스트 (Edge Case Testing)

- [ ] 입력값이 `null`, `undefined`, 빈 문자열(`""`), 0인 경우를 처리하는가?
- [ ] 배열이나 리스트의 인덱스 범위를 벗어나는 시나리오가 있는가?
- [ ] 네트워크 지연이나 API 호출 실패 시 에러 핸들링이 적절한가?

## 6. Claude 응답 가이드라인 (Response Strategy)

기능 구현 요청을 받았을 때, Claude는 다음과 같은 순서로 응답한다.

1. **코드 구현:** 요청받은 기능을 구현한 소스 코드를 제시한다.
2. **테스트 계획:** 해당 코드를 검증하기 위해 어떤 테스트를 수행할지 간략히 설명한다.
3. **테스트 코드 작성:** 구현된 코드를 검증하는 테스트 스크립트를 제공한다.
4. **검증 결과(시뮬레이션):** (실행 환경이 있는 경우) 테스트 실행 결과가 'PASS'임을 확인하거나, 논리적으로 결함이 없음을 증명한다.

---

## 7. 회귀 테스트 (Regression Testing)

- 새로운 기능을 추가할 때 기존에 작성된 테스트가 깨지지 않는지 확인한다.
- 만약 기존 기능의 수정이 필요하다면, 영향을 받는 다른 모듈의 테스트 케이스도 함께 업데이트한다.

---

## 8. 주의

테스트를 통과하지 못한 코드는 '완성'으로 간주하지 않으며, 반드시 디버깅 과정을 거쳐 테스트를 통과시킨 후 최종 코드를 제출한다.
